# Group 6 Warehouse AI — local prototype
Requires Python 3.9+; no pip installs or API keys. Run `python3 app.py`, open http://127.0.0.1:8000. Stop with Ctrl+C. Run `python3 test_engine.py` for isolated tests. To reset demo, stop server and delete warehouse.db, then restart.

Demo: track ORD-99182; cancel it; show pending ticket and unchanged order; approve; show cancelled and simulated refund. Use ORD-4092 to demonstrate failed payment fulfillment denial. Run workload 50, 500, 50 to show worker-pool sizing. Try ORD-6001 with cust_402 to demonstrate ownership check. Try a prompt injection or timeout. Export logs. For rejected cancellation reset database first or use another eligible order.

Implementation: stdlib HTTP server, SQLite, typed-by-convention request flow with rule-based triage, persisted ticket approval boundary, local thread pool. This is not a real LLM/LangGraph/RAG, AWS deployment, payment or shipping integration, or authenticated application. Demo customer selector and employee panel are trusted local roles; no public deployment. Prompt keyword checks are illustrative, not comprehensive. Queue is persistent but manual, no automatic retry consumer. Inventory is read-only; load test executes synthetic jobs, not concurrent purchases; no oversell claim. Refund approval is simulated. EDIT/REFUND/REVIEW approvals route to manual follow-up, not arbitrary writes. Measured response latency excludes human wait; local timings do not establish production KPIs. No actual AWS cost/uptime evidence. Next: integrate original LangGraph nodes and actual model, authenticated roles, retrieval, real AWS adapters, transactional inventory reservation and benchmarks.
